# vpn.io

**Самохостед персональный VPN — для себя и узкого круга.**
Десктоп-клиент в трее, mTLS-туннель и Telegram-бот, который раздаёт людям всё необходимое двумя файлами.

![release](https://img.shields.io/github/v/release/sodazzzzzz/vpn.io)

---

Пет-проект. Идея простая: поднимаешь свой VPN-сервер на арендованном VPS, а близкие подключаются без возни. Никакого терминала и никаких паролей после первой установки — человек получает от бота **установщик** и один **файл-профиль**, ставит приложение, перетаскивает профиль, жмёт **Connect**.

## Как это выглядит для друга

1. Пишет боту в Telegram свой одноразовый код-приглашение.
2. Получает в ответ **2 файла** — установщик под свою ОС и профиль `<имя>.vpnio`.
3. Ставит приложение (один раз — пароль администратора), открывает, перетаскивает профиль, жмёт **Connect**.

Всё. Дальше подключение — одна кнопка, без паролей и настроек.

## Что внутри

- **Самохостед и приватный.** Ты владеешь сервером и центром сертификации (CA), сам выпускаешь сертификаты. Корневой ключ CA не покидает доверенную машину (компромисс ради бота описан в [docs/BOT.md](docs/BOT.md)).
- **mTLS поверх TLS 1.3.** Сервер и клиент проверяют друг друга по одному CA — аутентификация по сертификату, без логинов и паролей.
- **Full-tunnel.** Сервер пушит клиенту маршруты (`0.0.0.0/0`) и DNS; клиент применяет их по-OS-но и аккуратно снимает на выходе.
- **Изоляция клиентов.** Hub-and-spoke с anti-spoof: каждый ходит в интернет через сервер, но адресовать других клиентов нельзя — пакеты «клиент→клиент» сервер дропает.
- **Привилегированный хелпер + GUI.** Туннель держит фоновая служба под root; графика работает под обычным пользователем и управляет ею через локальный IPC. Поэтому **Connect не спрашивает пароль**.
- **Отзыв сертификатов.** Любой выданный клиент отзывается одной командой (или из бота) — сервер дропает его на следующем коннекте.
- **Telegram-бот онбординга.** Раздаёт установщик под нужную ОС + профиль; owner-команды (`/invite`, `/revoke`, …) — управление без SSH.
- **Релизы и обновления.** Git-тег → CI собирает установщики и бинари → GitHub Release; на сервере одна команда `vpn-update`.
- **Устойчивый реконнект.** Экспоненциальный backoff + jitter, keepalive поверх TLS, перепин маршрута до сервера при смене сети (Wi-Fi обрыв/возврат).

## Дизайн клиента

Приложение — «тихий инструмент»: одна задача — мгновенно ответить «защищён ли я сейчас?» и дать одну кнопку, чтобы это изменить. Минимализм в духе Apple до эпохи «жидкого стекла», светлая/тёмная темы, честные статусы (включая ошибки с реальной причиной, а не «что-то пошло не так»), без анимаций ради анимаций. Подробнее — [docs/DESIGN.md](docs/DESIGN.md) и [docs/PRODUCT.md](docs/PRODUCT.md).

## Стек

- **Go 1.26** — сервер, CA, хелпер, бот и ядро клиента.
- **Wails v2** — десктоп-GUI (Go + HTML/CSS/JS, без Electron).
- **TLS 1.3 + mTLS** (`crypto/tls`, `crypto/x509`) — транспорт и аутентификация.
- **TUN** — `wireguard/tun`: utun (macOS), Wintun (Windows), `/dev/net/tun` (Linux).
- **IPC** — Unix-сокеты (macOS/Linux) и named pipes через `Microsoft/go-winio` (Windows).
- **Telegram** — `go-telegram-bot-api/v5`.
- **Установщики** — `pkgbuild` (`.pkg`), NSIS через Wails (`.exe`), `nfpm` (`.deb`).
- **Службы** — launchd (macOS), systemd (Linux), Windows Service.
- **CI/релизы** — GitHub Actions: пер-OS сборки, тег → GitHub Release.

## Компоненты

| Команда | Что делает |
|---|---|
| `vpn-server` | VPN-сервер (root): TUN, mTLS-листенер, full-tunnel, enforce отзыва. |
| `vpn-ca` | CA: `init`, `issue-server`, `issue-client`, `export-profile` (→ `.vpnio`), `revoke`. |
| `vpn-gui` | Десктоп-клиент (Wails), трей, управляет хелпером по IPC. |
| `vpn-helper` | Привилегированная фоновая служба — держит туннель. |
| `vpn-bot` | Telegram-бот онбординга (раздаёт установщик + профиль). |
| `vpn-client` | CLI-клиент (headless / отладка). |

## Установка и запуск

### Пользователю (друг)

Поставить установщик и импортировать профиль — пошагово по ОС в [docs/INSTALL.md](docs/INSTALL.md). Если используешь бота, он присылает оба файла сам — отдельно ничего качать не нужно.

### Владельцу (развёртывание)

Нужен **Go 1.26+**.

```bash
make build      # → ./bin/vpn-ca, vpn-server, vpn-client
```
(Десктоп-GUI собирается отдельно через Wails — см. `cmd/vpn-gui`.)

1. **CA** — на доверенной машине, один раз:
   ```bash
   vpn-ca init                                  # → ca-data/ca.crt, ca.key
   vpn-ca issue-server -hosts vpn.example.com   # серверный сертификат (домен/IP в SAN)
   vpn-ca issue-client -name alice              # клиентский сертификат
   vpn-ca export-profile -name alice \
          -server vpn.example.com:8443 -out alice.vpnio   # один файл-профиль
   ```
2. **Сервер** — на арендованном VPS (Linux): [docs/SERVER.md](docs/SERVER.md).
3. **Бот** — опционально, для самостоятельного онбординга людей: [docs/BOT.md](docs/BOT.md).
4. **Релизы и обновления** — тег → Release → `vpn-update` на сервере: [docs/RELEASES.md](docs/RELEASES.md).

### Попробовать локально (loopback)

Весь pipeline на одной машине:

```bash
make ca-init                                    # CA в ./ca-data/
make ca-server CA_HOSTS=localhost,127.0.0.1     # серверный сертификат
make ca-client CLIENT_NAME=alice                # клиентский сертификат

sudo make run-server PUSH_ROUTES=0.0.0.0/0 PUSH_DNS=1.1.1.1          # сервер (root для TUN)
sudo make run-client CLIENT_NAME=alice SERVER=127.0.0.1:8443 SERVER_NAME=localhost  # клиент
```

`make help` покажет все цели.
